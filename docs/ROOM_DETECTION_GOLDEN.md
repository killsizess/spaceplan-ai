# Эталоны определения помещений — SpacePlan AI 0.25.0

## Зачем

Помещения в режиме «По стенам» вычисляются булевыми операциями над следами стен (библиотека `polygon-clipping`). От результата зависят площади, ключи помещений, привязка названий, требования и даже допустимость сохранённого проекта. Тихое изменение — при обновлении библиотеки или правке нашего кода контуров — не должно дойти до пользователя незамеченным.

## Что сделано

- `src/domain/floor-plan/wall-rooms.fixtures.ts` — 11 эталонных планировок: прямоугольник, Г-образная комната, квартира с перегородкой, T-примыканием и обрубком стены, разная толщина стен, скошенный угол 45°, стены не по сетке и под небольшим углом, отдельно стоящая ширма (отверстие), коробка внутри комнаты (две комнаты и отверстие), разрыв 0,5 м (комнаты нет), волосяной разрыв 0,05 м (замыкается перекрытием стен), пример квартиры из приложения.
- `src/domain/floor-plan/wall-rooms.golden.json` — эталон: для каждой комнаты ключ, площадь, периметр, число вершин контура и отверстий, границы и граничные стены (числа округлены до 1e-6, сравнение с допуском 2e-6).
- `src/domain/floor-plan/wall-rooms.golden.test.ts`:
  - совпадение с эталоном для каждой планировки и отсутствие лишних или потерянных записей; пропавший файл эталона — ошибка, а не повод создать новый;
  - площади, посчитанные вручную: 18,24 м² прямоугольника; 24,65 м² Г-образной комнаты (включая свободный квадрат 0,1×0,1 у внутреннего угла, который оставляют прямые торцы стен); 8,51 и 12,21 м² при толщине 0,3/0,1 м; коробка 0,64 м² и отверстие 1,40 м² (1,2² минус четыре выреза 0,1×0,1 на внешних углах); ширма −0,6 м²; обрубок −0,28 м²; разрыв 0,5 м — нет комнаты, 0,05 м — комната есть;
  - инварианты для каждой планировки: площадь равна площади внешнего контура минус отверстия; граничные стены отсортированы и существуют; точка подписи внутри границ; обратный порядок и направление стен дают те же комнаты (допуск 1e-9); сдвиг всего плана на (123,4; −56,7) м даёт те же ключи и площади (допуск 1e-6).
- Версия `polygon-clipping` закреплена точно (`0.15.7` вместо `^0.15.7`), как остальные зависимости.

## Как принять намеренное изменение

1. Убедиться, что изменение ожидаемо (новая версия библиотеки, исправление контура).
2. Запустить `UPDATE_WALL_ROOM_GOLDEN=1` и тесты: в PowerShell `$env:UPDATE_WALL_ROOM_GOLDEN="1"; npx vitest run src/domain/floor-plan/wall-rooms.golden.test.ts`, затем удалить переменную.
3. Просмотреть разницу `wall-rooms.golden.json` построчно и описать её в README.

Существующие планировки не менять — добавлять новые, иначе эталон теряет смысл.

## Чего это не даёт

- Сохранённый проект в режиме «По стенам» по-прежнему отклоняется, если определение помещений падает. Загрузка с предупреждением вместо отказа — отдельное решение о поведении формата.
- Эталоны покрывают типовые случаи, а не любые данные распознавания с PDF; для них нужны будут собственные образцы, когда появится извлечение стен.
