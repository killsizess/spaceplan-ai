# Набор планов для замера точности

План продукта требует мерить точность распознавания на 30–50 настоящих планах, сравнивая с ручной разметкой. Здесь хранятся такие планы, а `npm run accuracy` считает по ним точность.

**Папка `bench/plans` не попадает в git**, кроме этого описания: репозиторий открыт, а планы клиентов конфиденциальны. Храните их у себя.

## Как добавить план

1. Откройте приложение, загрузите чертёж (PDF или DXF) и нажмите «Предложить стены», затем «Предложить двери и окна». Примите предложения. Приложение запомнит всё, что оно предложило, даже то, что вы потом удалите.
2. Исправьте план вручную, как он на самом деле устроен: удалите лишнее, добавьте пропущенное, поправьте стены.
3. На вкладке «Шаблон» нажмите «Подтвердить стены и проёмы». Подтверждённое и есть ручная разметка.
4. Экспортируйте проект в JSON и положите в `bench/plans/<имя>.json`.
5. Если в документах указаны площади комнат, положите рядом `bench/plans/<имя>.areas.json`:
   ```json
   [{ "name": "Кухня", "area": 10.1 }, { "name": "Гостиная", "area": 18.4 }]
   ```
   Имена должны совпадать с названиями комнат на плане.

## Как посчитать

```bash
npm run accuracy
```

Отчёт печатается и записывается в `bench/accuracy-report.md`, он тоже не в git. Другая папка: `ACCURACY_DIR=путь npm run accuracy`.

## Что считается

- **Стены по длине.** Полнота: какая доля метров подтверждённых стен была предложена. Точность: какая доля предложенных метров оказалась стенами. По длине, а не по штукам, потому что одна стена может прийти двумя кусками. Стена совпадает, если лежит на той же оси в пределах 10 см и под углом до 5°.
- **Двери и окна по штукам**, отдельно. Совпадает, если центр в пределах 30 см. Отдельно считается проём, найденный на месте, но не того вида.
- **Площади** против площадей из документа, по названию комнаты.

Предложения записываются в момент, когда их приняли, с версией приложения. Чтобы измерить новую версию распознавания, план нужно загрузить заново.
